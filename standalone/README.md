# standalone: i2r PLC 혼자 동작 (보드가 웹서버)

i2r PLC(i2r-02, i2r-03, i2r-04)를 **서버나 인터넷 없이** 같은 공유기의 휴대폰, PC에서 제어하는 펌웨어입니다.
보드가 직접 웹페이지를 띄우므로, 브라우저에서 `http://i2r.local`을 열면 i2r.link 장치 화면과 같은 화면이 나옵니다.

```
 휴대폰, PC (같은 Wi-Fi) ── http://i2r.local ──▶ i2r PLC (웹서버 + PLC)
                                                  ├─ 입력 규칙, 스케줄, 센서 트리거를 보드가 직접 실행
                                                  └─ 인터넷이 되면 시간만 NTP로 맞춤
```

| 버전 | `standalone-0.1.0` |
|---|---|
| 보드 | i2r-02, i2r-03, i2r-04 (폴더 `i2r-02/`, `i2r-03/`, `i2r-04/`) |
| 펌웨어 받기 | https://kdi.i2r.link/firmware 맨 아래 **i2r_server 펌웨어 → ① 혼자 동작** |
| 펌웨어 파일 | https://github.com/kdi6033/download/tree/main/i2r_server/standalone |

## 1. 바로 쓰기 (프로그램 없이)

1. 보드를 USB로 PC에 연결하고, 크롬이나 엣지에서 https://kdi.i2r.link/firmware 를 엽니다.
2. 맨 아래 **i2r_server 펌웨어 → ① 혼자 동작**에서 내 보드를 누르고 **COM 포트 선택하고 펌웨어 설치 시작**을 누릅니다.
   - 처음이면 **전체 설치**를 고릅니다. 보드에 저장된 설정이 모두 지워집니다.
   - 이미 standalone을 쓰고 있다면 **앱만 설치**로 바꾸면 Wi-Fi, 규칙, 스케줄, 이름이 그대로 남습니다.
3. 설치가 끝나면 바로 아래 **Wi-Fi 정보 보내기**에 SSID(공유기 이름)와 PW를 넣고 보냅니다. 2.4GHz Wi-Fi만 됩니다.
4. 보드가 다시 시작하면(약 10초) 같은 Wi-Fi의 휴대폰이나 PC에서 **http://i2r.local** 을 엽니다.
   - 안 열리면 공유기 관리 화면에서 보드 IP를 찾아 `http://192.168.x.x`로 엽니다.
   - 보드 LED: 계속 켜져 있으면 Wi-Fi 연결 중(또는 설정 없음), 1초에 한 번 깜박이면 연결됨.

## 2. 화면에서 하는 일

i2r.link 장치 화면과 배치와 순서가 같습니다.

| 화면 | 누르는 곳 | 하는 일 |
|---|---|---|
| 입력 상태 | 입력 이름 | **입력 규칙**: 입력이 켜질 때/꺼질 때 → 지연(초) 뒤 출력을 켜고/끄고, 동작 시간(초) 뒤 끄기 |
| 출력 제어 | 스위치 | 출력 켜고 끄기. 자동으로 꺼질 예정이면 남은 초가 보입니다 |
| 출력 제어 | 출력 이름 | **스케줄**: 기기 현재 시간, 시간대 고르기, 동기화, 매일/매주(요일) 시작~종료 시간에 켜기 |
| 온도, 습도 (i2r-03) | 카드 | **센서 트리거**: 올라갈 때/내려갈 때 출력 바꾸기. **보정**(선택): 값이 틀릴 때 실제 값을 넣음 |
| 기기 이름 옆 ⚙ | | 기기 이름, 입력과 출력 이름 바꾸기 |

예
- "현관 센서(IN1)가 켜지면 3초 뒤 전등(OUT2)을 1분 켜기" → 입력 1 → 켜짐, 출력 2, 켜짐, 지연 3, 동작시간 60
- "평일 저녁 6시~10시 전등 켜기" → 출력 이름 → 매주, 월~금, 18:00:00 ~ 22:00:00
- "온도 30도 이상이면 팬(OUT3) 켜고 25도 이하면 끄기" → 온도 카드 → ⬆️ 30 켜짐, ⬇️ 25 꺼짐 (두 개 등록)

## 3. 동작 방식

| 항목 | 내용 |
|---|---|
| 시간 | 켜질 때와 **1시간마다** 인터넷 시간(NTP)으로 맞춥니다. 인터넷이 없으면 보드 시계로 계속 돌고, **10분마다** 시각을 저장해 다시 켜도 이어 갑니다 (꺼져 있던 시간만큼 늦어지므로 스케줄 창의 "동기화"로 맞춥니다) |
| 스케줄 | 시간대에 **들어가는 순간 켜고 벗어나는 순간 끕니다**. 그 사이 사람이 바꾼 출력은 건드리지 않습니다. 22:00~06:00처럼 자정을 넘어도 됩니다. 시간을 모르면 쉽니다 |
| 입력 규칙 | 입력이 트리거 값이 **되는 순간** 지연을 셉니다. 기다리는 중 다시 바뀌면 처음부터 셉니다 |
| 센서 트리거 | 기준 값을 **넘는 순간** 한 번 실행합니다. 등록할 때 이미 기준 이상이면 "올라갈 때"가 곧바로 실행됩니다. 센서는 2초마다 읽습니다 |
| 저장 | 규칙, 스케줄, 센서 트리거(각 40개까지), 보정, 이름, Wi-Fi는 보드에 저장되어 전원이 꺼져도 남습니다 |
| Wi-Fi | USB로 받은 설정에서 **SSID와 PW만** 저장합니다. Email, Broker 칸은 무엇을 넣어도 저장하지 않습니다 |
| 끊김 | Wi-Fi가 끊겨도 PLC, 규칙, 스케줄은 계속 돌고, 30초마다 다시 연결합니다 |

## 4. 웹 API (프로그램을 고치거나 다른 앱에서 쓸 때)

| 주소 | 내용 |
|---|---|
| `GET /` | 화면 (`page.h`) |
| `GET /state` | 상태 JSON. 화면이 1초마다 읽습니다 |
| `POST /cmd` | 명령 JSON 한 개를 보내면 답 JSON 한 개 |
| `GET /logo.png` | 로고 (`logo.h`) |

상태 예
```json
{"m":"AA:BB:CC:DD:EE:FF","t":"i2r-03","ver":"standalone-0.1.0",
 "name":["i2r-03","입력 1","입력 2","입력 3","입력 4","출력 1","출력 2","출력 3","출력 4"],
 "in":[0,0,0,0],"out":[1,0,0,0],"remain":[0,0,0,0],"sensor":true,"temp":27.6,"humi":23.6,
 "time":"13:51:42","tz":32400,"tsrc":"ntp","ntpAgo":79,"ip":"192.168.0.10","rssi":-28}
```
- `tsrc`: 시간을 어디서 받았는지 (`ntp` 인터넷, `saved` 저장된 시각, `web` 화면 동기화, `none` 모름)

명령은 [i2r 프로토콜](../protocol.md)과 같은 모양입니다. **번호는 0부터** (`"n":0` = OUT1).

| 명령 | 예 | 답 |
|---|---|---|
| `gs` 상태 | `{"c":"gs"}` | 상태 |
| `so` 출력 | `{"c":"so","n":0,"v":1,"d":5}` (5초 뒤 저절로 끔, `d` 없으면 계속) | 상태 |
| `st` 시간 | `{"c":"st","epoch":현지epoch,"tz":32400}` | 상태 |
| `bio` 입력 규칙 | `{"c":"bio","o":"insert","n":0,"tr":1,"d":3,"du":60,"ps":[{"n":1,"v":1}]}` / `list` / `delete`(`sI`) / `deleteAll` | 목록 `items` |
| `sch` 스케줄 | `{"c":"sch","o":"insert","pi":0,"start":64800,"end":79200,"rm":"weekly","dw":[1,2,3,4,5]}` / `list` / `delete`(`sI`=목록 `index`) / `deleteAll` | 목록 `items` |
| `bs` 센서 트리거 | `{"c":"bs","o":"insert","ts":"temp","tr":1,"tv":30,"ps":[{"n":2,"v":1}]}` / `list` / `delete` / `deleteAll` / `cali`(`v`) | 목록 `items` (cali는 상태) |
| `name` 이름 | `{"c":"name","name":["전등","입력 1",…]}` (이 펌웨어만) | 상태 |

- 프로토콜과 다른 점: 목록은 `items` 배열 하나로 한 번에 답하고, insert와 delete 뒤에도 목록을 돌려줍니다. 규칙의 대상은 이 보드의 출력만 됩니다.
- 실패하면 `{"c":"err","re":"so","code":"bad_n"}` (코드는 protocol.md 7장, 그리고 `no_sensor`, `too_long`, `json`).
- 시리얼(USB, 115200)에 같은 JSON 한 줄을 보내도 같은 답이 옵니다. Wi-Fi 설정 `{"c":"si","ssid":"..","password":".."}`는 **USB에서만** 받습니다.

## 5. 소스와 직접 컴파일

| 파일 | 내용 |
|---|---|
| `i2r-0X/i2r-0X.ino` | 보드 프로그램. 세 폴더는 `#define I2R_BOARD` 한 줄만 다릅니다 |
| `i2r-0X/page.h` | 웹 화면 (HTML, CSS, JS 한 파일, 외부 파일 없이 인터넷 없이도 동작) |
| `i2r-0X/logo.h` | 로고 이미지 |
| `i2r-0X/secrets.example.h` | 개발용 Wi-Fi 견본 (`secrets.h`로 복사해 쓰고, GitHub에 올리지 않음) |
| `CLAUDE.md` | Claude가 이 예제로 프로그램을 만드는 순서와 코드 지도 |

필요한 라이브러리(라이브러리 매니저): **I2R_PLC, I2R_IoT, ArduinoJson, PubSubClient**
보드 설정: ESP32 Dev Module, Flash 8MB, Partition **Huge APP**

```
arduino-cli compile --fqbn esp32:esp32:esp32:FlashSize=8M,PartitionScheme=huge_app standalone/i2r-03
arduino-cli upload -p COM3 --fqbn esp32:esp32:esp32:FlashSize=8M,PartitionScheme=huge_app standalone/i2r-03
```

저장 자리(NVS): `i2rweb` 규칙·스케줄·센서 트리거·보정·이름 / `i2riot` Wi-Fi (I2R_IoT와 같음) / `i2r` 시간대·저장된 시각 (I2R_Time)

## 7. 주의

- 같은 Wi-Fi에 붙은 사람은 누구나 이 화면으로 릴레이를 켤 수 있습니다 (비밀번호 없음, HTTP). **공용 Wi-Fi에서 쓰지 마세요.**
- 같은 공유기에 i2r 보드가 여러 대면 `i2r.local` 이름이 겹칩니다. 소스의 `HOST_NAME`을 보드마다 다르게 바꿉니다 (`i2r-kitchen` → `http://i2r-kitchen.local`).
- 업로드, 설치 전에 릴레이에 연결된 장치가 켜져도 괜찮은지 확인하세요. 저장된 스케줄이나 규칙이 켜자마자 동작할 수 있습니다.
- i2r-02, i2r-04 입력은 무전압 접점입니다. 입력 단자에 전압을 넣지 마세요 (보드 고장).
