# i2r 시뮬레이터

PC에서 **가상 i2r 보드**를 띄웁니다. 실제 보드와 똑같이 MQTT 서버에 붙어 i2r 프로토콜을 주고받습니다.
보드 없이도 화면, 서버, 여러 대 연동을 시험할 수 있고, 실제 릴레이가 움직이지 않아 안전합니다.

```
가상 보드 1 ─┐
가상 보드 2 ─┼─ MQTT 서버 (test.mosquitto.org / i2r-05 / 아마존) ─ HiveMQ 웹, 서버, 대시보드
실제 i2r-03 ─┘
```

## 켜는 방법

| 방법 | 하는 일 |
|---|---|
| **Claude에게** | "시뮬레이터 켜 줘" (Python이 없으면 Claude가 설치) |
| **두 번 누르기** | `start-sim.bat` (Python 필요. 창을 닫으면 꺼짐) |
| **터미널** | `python sim.py` |

켜지면 브라우저에서 **http://localhost:8000** 이 저절로 열립니다.

## 화면

- **입력 스위치(IN1~IN4)**: 누르면 가상 입력이 켜집니다. 실제 단자에 전압을 넣은 것과 같습니다. 상태 메시지가 서버로 나갑니다.
- **출력 LED(OUT1~OUT4)**: 서버에서 온 `so` 명령으로 켜집니다. 실제 릴레이 대신입니다. 유지 시간(`d`)이 있으면 남은 초가 보입니다.
- **온도 ±1, 습도 ±1**: 가상 측정값을 바꿉니다 (온도 0.2도, 습도 1% 이상 바뀌면 상태를 보냄). 보내는 값은 측정값 + 보정값입니다.
- **받은 명령, 보낸 메시지**: 제어 화면과 가상 보드 카드마다 마지막 메시지 하나를 보여 줍니다.
- **입력 규칙**: 제어 화면에서 **입력 N**을 누르면 설정 창이 열립니다. i2r.link의 입력 설정과 같습니다.
  "입력 1이 켜지면 → 3초 뒤 → 보드 2의 스위치 1을 켜고 → 5초 동안" 같은 규칙을 등록, 보기, 삭제합니다.
  가상 보드 카드의 "입력 규칙"에 그 보드의 규칙과 남은 시간이 보입니다.
- **시간표**: 제어 화면에서 **스위치 N** 이름을 누르면 시간표 창이 열립니다. i2r.link의 스위치 시간표와 같습니다.
  "09:00:00 ~ 17:00:00 매일", "매주 월, 수요일" 같은 스케줄을 저장, 보기, 삭제합니다.
  가상 보드 카드에 그 보드의 시간표와 **보드 시각**이 보입니다.
- **센서 트리거, 보정**: 제어 화면에서 **온도**나 **습도** 카드를 누르면 설정 창이 열립니다. i2r.link의 센서 트리거와 같습니다.
  "온도가 30도로 올라갈 때 → 스위치 1 켜기", "습도가 40%로 내려갈 때 → 3초 뒤 스위치 2 켜기" 같은 트리거를 등록하고,
  아래 **보정**에 지금 실제 값을 넣으면 그 차이를 보정값으로 저장합니다.

## 입력 규칙 (bio)

실제 보드 펌웨어(BioManager)와 같은 형식입니다. 번호(`n`)는 0부터입니다.

```
등록    {"c":"bio","o":"insert","m":이보드,"n":0,"tr":1,"d":3,"du":5,"ps":[{"m":대상보드,"n":0,"v":1}]}
목록    {"c":"bio","o":"list","m":이보드,"n":0}        → 규칙마다 한 줄씩 0.2초 간격
하나    {"c":"bio","o":"delete","m":이보드,"n":0,"sI":1}
모두    {"c":"bio","o":"deleteAll","m":이보드,"n":0}
```

- 입력 `n`이 `tr`과 같아지면 `d`초 뒤 대상 출력을 `v`로 바꾸고, `du`초가 지나면 끕니다 (`du` 0 = 계속). 기다리는 동안 다시 들어오면 처음부터 셉니다.
- 대상이 다른 보드면 `{"c":"so","m":대상,...}`를 in 토픽으로 보냅니다. 가상 보드끼리, 가상 보드와 실제 보드 사이에도 됩니다.
- 실제 보드처럼 `insert`에는 답하지 않습니다. 잘못된 값이면 `err bad_n`, `bad_v`, `bad_o`, `bad_si`, `full`(40개 넘음).
- 규칙은 메모리에만 있어서 시뮬레이터를 끄면 사라집니다.

## 시간표 (sch)

실제 보드 펌웨어(TimeSlotManager)와 같은 형식입니다. 출력 번호는 `pi`(0부터), 시간은 0시부터 센 **초**입니다 (오전 9시 = 32400).

```
저장    {"c":"sch","o":"insert","m":이보드,"pi":0,"start":32400,"end":61200,"rm":"daily"}
        {"c":"sch","o":"insert","m":이보드,"pi":0,"start":32400,"end":61200,"rm":"weekly","dw":[1,3]}
목록    {"c":"sch","o":"list","m":이보드,"pi":0}
        → {"c":"sch","o":"list","pi":0,"index":0,"start":32400,"end":61200,"rm":"daily","dw":-1,"pn":"1/2"}
하나    {"c":"sch","o":"delete","m":이보드,"pi":0,"sI":0}     sI = 목록의 index
모두    {"c":"sch","o":"deleteAll","m":이보드,"pi":0}
```

- 요일 `dw`는 0 = 일요일 ~ 6 = 토요일입니다. 매주 반복은 요일마다 한 줄씩 저장됩니다.
- 시간대에 들어가는 순간 출력을 켜고, 벗어나는 순간 끕니다. 종료가 시작보다 이르면 자정을 넘는 시간대입니다 (예: 22시 ~ 6시).
- 실제 보드처럼 `insert`, `delete` 뒤에는 목록을 다시 보내고, `deleteAll` 뒤에는 보내지 않습니다.
- 보드 시각은 PC 시계에 `tz`(기본 한국 시간)를 더한 값입니다. 시간표도 메모리에만 있습니다.

## 센서 트리거, 보정 (bs)

실제 보드 펌웨어(SensorManager)와 같은 형식입니다. 센서는 `ts`로 고릅니다 (`temp`, `humi`. `temperature`, `humidity`도 받음).

```
등록    {"c":"bs","o":"insert","m":이보드,"ts":"temp","tr":1,"tv":30,"d":0,"du":0,"ps":[{"m":대상보드,"n":0,"v":1}]}
목록    {"c":"bs","o":"list","m":이보드,"ts":"temp"}     → 트리거마다 한 줄씩
        → {"c":"bs","o":"list","ts":"temp","tr":1,"tv":30,"d":0,"du":0,"sI":0,"ps":[{"m":..,"n":0,"v":1}]}
하나    {"c":"bs","o":"delete","m":이보드,"ts":"temp","sI":0}
모두    {"c":"bs","o":"deleteAll","m":이보드,"ts":"temp"}
보정    {"c":"bs","o":"cali","m":이보드,"ts":"temp","v":28.1}    지금 값이 28.1이 되도록 보정
```

- `tr` 1 = **올라갈 때**(값이 `tv` 아래에서 `tv` 이상이 되는 순간), 0 = **내려갈 때**(`tv` 위에서 `tv` 이하가 되는 순간). 넘는 순간에만 실행합니다.
- `d`초 뒤 대상 출력을 `v`로 바꾸고, `du`초가 지나면 끕니다 (0 = 계속). 대상이 다른 보드면 `so`를 보냅니다.
- 번호 `sI`는 실제 보드처럼 0부터입니다. `insert`에는 답하지 않습니다. `ps`는 하나만 받습니다.
- **실제 보드와 같은 점 주의**: 처음 값을 -1로 보기 때문에, 등록할 때 이미 기준값 이상이면 "올라갈 때" 트리거가 곧바로 한 번 실행됩니다.
- 보정은 보정 뒤 바로 상태를 보냅니다. 트리거도 보정된 값으로 판단합니다. 트리거와 보정값도 메모리에만 있습니다.

## 옵션

```
python sim.py --boards 3                          가상 보드 3대 (공개 서버는 5대까지)
python sim.py --server broker.emqx.io             다른 공개 서버 (test.mosquitto.org가 안 될 때)
python sim.py --server 192.168.0.50               i2r-05 로컬 서버
python sim.py --server 내서버 --user 아이디       아이디·비밀번호가 있는 서버 (비밀번호는 묻는다)
python sim.py --kind i2r-04                       i2r-04 (입출력 8개)
python sim.py --group home1                       그룹 정하기 (기본: 실행할 때마다 sim-임의코드)
python sim.py --lan                               같은 공유기의 휴대폰에서도 화면 열기
python sim.py --no-web                            화면 없이 (자동 시험용)
```

- 가상 보드 MAC은 `02:`로 시작합니다. "직접 정한 주소"라 실제 기기와 겹치지 않습니다.
- 공개 서버에서는 그룹이 실행할 때마다 바뀌어 다른 사람의 가상 보드와 섞이지 않습니다.

## 규칙 시험

가상 보드와 실제 보드에 똑같이 씁니다 (i2r.md 5.5 규칙).

```
python test_protocol.py --server broker.emqx.io --group sim-6194 --mac 02:F1:61:4D:6F:01
```

| 시험 | 기대 |
|---|---|
| `gs` (MAC 있음, 없음) | 상태 (m, fr, t, e 포함) |
| `so` 켜기, 끄기 | 상태에 반영 |
| `so` MAC 없음 | `err no_m`, 출력 그대로 |
| `so` 다른 보드 MAC | 무시 |
| `so` `"m":"*"` | 실행 |
| 없는 번호, 값 범위 밖 | `err bad_n`, `err bad_v` |
| `id` 붙인 명령 | 답에 같은 `id` |
| 모르는 명령 | `err unknown` |
| `so` `d=2` | 켜졌다가 2초 뒤 저절로 꺼짐 |
| `fr`이 자기 MAC | 무시 |
| `bio` insert, delete, deleteAll | list에 반영 |
| `sch` insert(매일, 매주), delete, deleteAll | 목록에 반영 |
| `bs` insert, delete, deleteAll | 목록에 반영 (온도 센서가 있는 보드만) |
| `bs` 보정 | 상태의 온도가 바뀜 (가상 보드만, 시험 뒤 되돌림) |

실제 보드에 할 때는 **릴레이에 아무것도 연결하지 않은 상태**에서 합니다.
